# Pad-number and placeholder follow-up

The queried public property is correct: `Pad` parses `a.positional("number",R.string)` at app/public/dependencies/kicanvas.js:961, then Object.assign(this,r). The only Pad getters immediately following are unique_id and netname. Footprint indexes its pads with `this.#e.set(r.number,r)` at the same line, and the painter passes `r.number` to draw_net_name at line 1105. This is not a .number.text or .number.value object.

The S-expression tokenizer turns unquoted numeric tokens into parseFloat numbers (line 956), listify stores token.value primitives (line 960), and R.string only returns values passing `typeof s == "string"` (lines 960 and 1). Thus unquoted `(pad 1 ...)` yields an undefined Pad.number, while `(pad "1" ...)` yields string "1". Runtime samples show exactly that: ProMicro pad token 1 has number undefined (captured as null), whereas ceoloide:switch_mx token "1" has number "1". Their enumerable fields both contain number, shape, at, size, drill, layers, and net. The existing observation is supported, although this follow-up does not apportion responsibility between source emission and viewer input compatibility or quantify downstream effects.
